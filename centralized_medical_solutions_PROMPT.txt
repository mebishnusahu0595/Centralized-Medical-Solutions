SECTION 3 — USER ROLES & PERMISSIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ROLE 1: super_admin
  Who   : The company (you) — single account
  Access: Everything across ALL hospitals
  Can   :
    - Create/suspend/delete hospital accounts
    - View all equipment across all hospitals
    - View all users across all hospitals
    - Access global revenue & usage analytics
    - Manage subscription plans
    - Send global announcements
    - Access audit logs (all activity)
    - Force reset passwords
    - Manually trigger maintenance alerts
  Cannot: Nothing is restricted for super_admin

ROLE 2: hospital_admin
  Who   : Hospital owner / manager
  Access: ONLY their own hospital (tenant isolation enforced)
  Can   :
    - Add/edit/delete equipment
    - Add/edit/deactivate users (engineers, staff)
    - Assign equipment to engineers
    - View all reports for their hospital
    - Download PDF reports
    - Configure hospital settings (name, contact, logo)
    - View maintenance schedule
    - Set compliance deadlines
    - Upload hospital documents
  Cannot:
    - See other hospitals' data
    - Access billing (managed by super_admin)
    - Create hospital_admin accounts (only super_admin can)

ROLE 3: engineer
  Who   : Biomedical engineer / technician
  Access: Only equipment assigned to them + shared hospital pool
  Can   :
    - View assigned equipment
    - Submit service reports (with photos, notes, digital signature)
    - Update equipment status
    - Mark maintenance complete
    - Upload images and PDFs per equipment
    - Add repair notes with timestamps
  Cannot:
    - Add or delete equipment
    - Manage users
    - View financial/analytics data
    - Access other engineers' assignments

ROLE 4: staff (viewer)
  Who   : Nurses, ward managers, non-technical hospital staff
  Access: Read-only dashboard for their hospital
  Can   :
    - View equipment list and status
    - View maintenance schedule
    - Raise an equipment issue/complaint (creates a ticket)
  Cannot:
    - Edit anything
    - View service reports in detail
    - Export data

SECTION 4 — MONGODB DATA MODELS (Mongoose Schemas)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

All schemas use TypeScript interfaces. Define in /backend/src/models/

── Hospital ──────────────────────────────────────────────
{
  _id          : ObjectId
  name         : String (required, unique)
  code         : String (auto-generated short code e.g. "AIIMS-DEL-001")
  address      : { street, city, state, pincode, country }
  contactEmail : String
  contactPhone : String
  logo         : String (URL path)
  subscriptionPlan : enum ["free", "basic", "pro", "enterprise"]
  subscriptionStatus : enum ["active", "suspended", "expired"]
  subscriptionExpiry : Date
  isActive     : Boolean (default: true)
  createdBy    : ObjectId → User (super_admin)
  settings     : {
    timezone   : String (default: "Asia/Kolkata")
    currency   : String (default: "INR")
    dateFormat : String (default: "DD/MM/YYYY")
  }
  timestamps   : createdAt, updatedAt
}

── User ──────────────────────────────────────────────────
{
  _id          : ObjectId
  hospitalId   : ObjectId → Hospital (null for super_admin)
  name         : String
  email        : String (unique)
  phone        : String
  passwordHash : String (bcrypt, 12 rounds)
  role         : enum ["super_admin","hospital_admin","engineer","staff"]
  isActive     : Boolean (default: true)
  avatar       : String (URL)
  refreshToken : String
  lastLogin    : Date
  createdBy    : ObjectId → User
  timestamps   : createdAt, updatedAt
}

── Equipment ─────────────────────────────────────────────
{
  _id              : ObjectId
  hospitalId       : ObjectId → Hospital (required — tenant key)
  name             : String (required)
  category         : enum [
                       "imaging", "monitoring", "laboratory",
                       "surgical", "life_support", "diagnostic",
                       "rehabilitation", "sterilization", "other"
                     ]
  subCategory      : String
  equipmentCode    : String (auto-generated unique per hospital)
  serialNumber     : String
  modelNumber      : String
  manufacturer     : String
  vendor           : String
  purchaseDate     : Date
  purchasePrice    : Number
  warrantyExpiry   : Date
  location         : { building, floor, ward, room }
  status           : enum ["active","under_maintenance","out_of_service","decommissioned"]
  condition        : enum ["excellent","good","fair","poor"]
  assignedEngineer : ObjectId → User (engineer)
  maintenanceFrequency : enum ["weekly","monthly","quarterly","biannual","annual"]
  lastMaintenanceDate  : Date
  nextMaintenanceDate  : Date (auto-calculated)
  complianceDueDate    : Date
  documents        : [{ name, url, type, uploadedAt }]
  images           : [String] (URL array)
  qrCode           : String (generated)
  barcode          : String
  tags             : [String]
  isActive         : Boolean (default: true)
  addedBy          : ObjectId → User
  timestamps       : createdAt, updatedAt
}

── MaintenanceLog ────────────────────────────────────────
{
  _id           : ObjectId
  hospitalId    : ObjectId → Hospital
  equipmentId   : ObjectId → Equipment
  engineerId    : ObjectId → User
  type          : enum ["preventive","corrective","emergency","calibration","inspection"]
  status        : enum ["scheduled","in_progress","completed","cancelled"]
  scheduledDate : Date
  startedAt     : Date
  completedAt   : Date
  duration      : Number (minutes)
  workDone      : String (detailed description)
  partsReplaced : [{ partName, partNo, cost }]
  totalCost     : Number
  beforeImages  : [String]
  afterImages   : [String]
  pdfReport     : String (URL)
  signature     : String (base64 digital signature)
  nextDueDate   : Date
  remarks       : String
  verifiedBy    : ObjectId → User (admin)
  timestamps    : createdAt, updatedAt
}

── ServiceReport ─────────────────────────────────────────
{
  _id           : ObjectId
  hospitalId    : ObjectId → Hospital
  equipmentId   : ObjectId → Equipment
  reportedBy    : ObjectId → User
  assignedTo    : ObjectId → User (engineer)
  issueType     : enum ["breakdown","performance","calibration","routine","compliance"]
  priority      : enum ["low","medium","high","critical"]
  status        : enum ["open","assigned","in_progress","resolved","closed"]
  title         : String
  description   : String
  attachments   : [String]
  resolution    : String
  resolvedAt    : Date
  sla           : { targetHours: Number, breached: Boolean }
  timestamps    : createdAt, updatedAt
}

── Notification ─────────────────────────────────────────
{
  _id           : ObjectId
  hospitalId    : ObjectId → Hospital (null = global)
  userId        : ObjectId → User (target user, null = broadcast)
  type          : enum [
                    "maintenance_due","warranty_expiry","compliance_alert",
                    "equipment_breakdown","service_assigned",
                    "report_submitted","subscription_expiry","system"
                  ]
  title         : String
  message       : String
  isRead        : Boolean (default: false)
  link          : String (relative URL to click)
  createdAt     : Date
}

── AuditLog ─────────────────────────────────────────────
{
  _id           : ObjectId
  hospitalId    : ObjectId → Hospital
  userId        : ObjectId → User
  action        : String (e.g. "EQUIPMENT_CREATED", "USER_DELETED")
  resource      : String (e.g. "Equipment")
  resourceId    : ObjectId
  oldData       : Mixed (before state)
  newData       : Mixed (after state)
  ipAddress     : String
  userAgent     : String
  timestamp     : Date
}

SECTION 5 — BACKEND API ROUTES (Express.js)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Base URL: /api/v1

All protected routes require: Authorization: Bearer <accessToken>
All routes enforce role-based middleware before controller

── AUTH ───────────────────────────────────────────────────
POST   /auth/login                → Login (all roles)
POST   /auth/logout               → Logout (clear refresh token)
POST   /auth/refresh              → Get new access token
POST   /auth/forgot-password      → Send OTP/reset link
POST   /auth/reset-password       → Set new password
GET    /auth/me                   → Get current user profile
PATCH  /auth/change-password      → Change own password

── HOSPITALS (super_admin only) ──────────────────────────
GET    /hospitals                 → List all hospitals (paginated)
POST   /hospitals                 → Create hospital + create admin account
GET    /hospitals/:id             → Get hospital detail
PATCH  /hospitals/:id             → Update hospital
DELETE /hospitals/:id             → Soft delete hospital
PATCH  /hospitals/:id/suspend     → Suspend/unsuspend hospital
GET    /hospitals/:id/stats       → Equipment + user stats for hospital

── USERS ─────────────────────────────────────────────────
GET    /users                     → List users (filtered by hospital for admin)
POST   /users                     → Create user (admin creates engineer/staff)
GET    /users/:id                 → Get user detail
PATCH  /users/:id                 → Update user
DELETE /users/:id                 → Deactivate user
POST   /users/:id/reset-password  → Force reset password (admin/super_admin)

── EQUIPMENT ─────────────────────────────────────────────
GET    /equipment                 → List equipment (hospital-scoped)
POST   /equipment                 → Add new equipment
GET    /equipment/:id             → Get equipment detail + full history
PATCH  /equipment/:id             → Update equipment
DELETE /equipment/:id             → Decommission equipment
POST   /equipment/:id/documents   → Upload document (multer)
POST   /equipment/:id/images      → Upload images (multer, max 5)
GET    /equipment/:id/qr          → Get QR code for equipment
GET    /equipment/export          → Export equipment list as PDF or Excel
PATCH  /equipment/:id/assign      → Assign engineer to equipment

── MAINTENANCE ────────────────────────────────────────────
GET    /maintenance               → List maintenance logs (filterable)
POST   /maintenance               → Create maintenance log
GET    /maintenance/:id           → Get log detail
PATCH  /maintenance/:id           → Update log (engineer updates)
PATCH  /maintenance/:id/complete  → Mark complete + upload signature
POST   /maintenance/:id/report    → Generate PDF report (puppeteer)
GET    /maintenance/calendar      → Get maintenance calendar view (month)
GET    /maintenance/upcoming      → Upcoming maintenance (next 30 days)

── SERVICE REPORTS ────────────────────────────────────────
GET    /service-reports           → List all reports (hospital-scoped)
POST   /service-reports           → Raise new issue/complaint
GET    /service-reports/:id       → Get report detail
PATCH  /service-reports/:id       → Update report
PATCH  /service-reports/:id/assign   → Assign to engineer
PATCH  /service-reports/:id/resolve  → Resolve report

── NOTIFICATIONS ──────────────────────────────────────────
GET    /notifications             → Get user's notifications (paginated)
PATCH  /notifications/read-all    → Mark all as read
PATCH  /notifications/:id/read    → Mark one as read
DELETE /notifications/:id         → Delete notification

── ANALYTICS ──────────────────────────────────────────────
GET    /analytics/dashboard       → Dashboard KPIs (role-aware)
GET    /analytics/equipment       → Equipment stats (by category, status)
GET    /analytics/maintenance     → Maintenance stats (completion rate, SLA)
GET    /analytics/hospitals       → (super_admin) All hospital stats
GET    /analytics/compliance      → Compliance status across hospital

── AUDIT LOGS ─────────────────────────────────────────────
GET    /audit-logs                → Paginated audit log (hospital-scoped or global)

SECTION 6 — REAL-TIME (Socket.io)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Socket.io runs on same Express server.
Clients join rooms based on hospitalId after authentication.

Room naming:
  hospital:{hospitalId}    → all users in a hospital
  user:{userId}            → private notifications

Events the server EMITS:
  notification:new         → { notification object }
  maintenance:due          → { equipmentId, equipmentName, daysLeft }
  equipment:status_changed → { equipmentId, oldStatus, newStatus, changedBy }
  service:assigned         → { reportId, title, assignedTo }
  service:resolved         → { reportId, title }
  dashboard:refresh        → triggers client to refetch dashboard stats

Events the client SENDS:
  join:hospital            → { hospitalId, token }
  notification:mark_read   → { notificationId }

SECTION 9 — BUSINESS LOGIC & AUTOMATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

MAINTENANCE DATE CALCULATION:
  When equipment is added OR maintenance is completed:
  nextMaintenanceDate = lastMaintenanceDate + maintenanceFrequency
  Frequencies: weekly=7d, monthly=30d, quarterly=90d, biannual=180d, annual=365d

AUTOMATED CRON JOBS (node-cron):
  Every day at 8:00 AM IST:
    - Check all equipment nextMaintenanceDate
    - If due within 7 days → create notification (maintenance_due)
    - If overdue → create notification (priority: critical) + email admin
    - Check warrantyExpiry → alert if expiring within 30 days
    - Check complianceDueDate → alert if due within 14 days
    - Check subscription expiry → alert hospital admin if expiring in 7 days

EQUIPMENT STATUS AUTO-LOGIC:
  When maintenance log created → equipment status → "under_maintenance"
  When maintenance marked complete → equipment status → "active"
  When service report priority "critical" raised → equipment status → "out_of_service"
  When equipment decommissioned → status → "decommissioned" (permanent, no edit)

TENANT ISOLATION (CRITICAL SECURITY):
  Every database query that is NOT super_admin must include:
    { hospitalId: req.user.hospitalId }
  Middleware function: enforceHospitalScope(req, res, next)
  This must be applied to EVERY equipment, maintenance, user, report route
  super_admin bypasses this middleware

QR CODE GENERATION:
  On equipment creation, generate QR code using 'qrcode' npm package
  QR encodes: { equipmentId, hospitalId, name, equipmentCode }
  Store as base64 PNG in equipment.qrCode field
  Engineers can scan QR to directly open equipment detail page on mobile

SLA FOR SERVICE REPORTS:
  critical → resolve within 4 hours
  high     → resolve within 24 hours
  medium   → resolve within 72 hours
  low      → resolve within 7 days
  On creation, calculate sla.targetTime = createdAt + hours
  Cron every hour checks open reports → marks sla.breached = true if overdue
  Breached SLA sends notification to admin

SECTION 11 — SECURITY REQUIREMENTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Passwords: bcrypt with 12 salt rounds — never store plaintext
2. JWT: access token 15min, refresh token 7d, store refresh in httpOnly cookie
3. Rate limiting: express-rate-limit — 100 req/15min per IP on auth routes
4. Helmet.js: set secure HTTP headers
5. CORS: whitelist only your domain(s)
6. Input validation: Zod on every route body/query/params
7. File upload: validate MIME type and file size (images max 5MB, docs max 20MB)
8. Tenant isolation: enforceHospitalScope middleware on every data route
9. Audit log: every create/update/delete action gets logged with user + IP
10. XSS protection: sanitize all user text inputs (DOMPurify or validator.js)
11. MongoDB injection: use Mongoose (parameterized), never raw string queries

STEP 1 — Install prerequisites on VPS:
  sudo apt update && sudo apt upgrade -y
  sudo apt install -y nodejs npm nginx certbot python3-certbot-nginx mongodb
  sudo systemctl enable mongod && sudo systemctl start mongod
  npm install -g pm2 typescript

STEP 2 — Clone and build:
  git clone <your-repo> /var/www/cms-platform
  cd /var/www/cms-platform/backend && npm install && npm run build
  cd /var/www/cms-platform/frontend && npm install && npm run build

STEP 3 — Start processes with PM2:
  pm2 start dist/server.js --name "cms-backend"
  pm2 start npm --name "cms-frontend" -- start
  pm2 save && pm2 startup

STEP 4 — Nginx config (/etc/nginx/sites-available/cms):
  server {
    listen 80;
    server_name yourdomain.com;

    location /api {
      proxy_pass http://localhost:5000;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection 'upgrade';
      proxy_set_header Host $host;
      proxy_cache_bypass $http_upgrade;
    }

    location /socket.io {
      proxy_pass http://localhost:5000;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
    }

    location / {
      proxy_pass http://localhost:3000;
      proxy_set_header Host $host;
    }

    location /uploads {
      alias /var/www/cms-uploads;
      add_header Cache-Control "public, max-age=86400";
    }
  }

STEP 5 — SSL:
  sudo certbot --nginx -d yourdomain.com
  (auto-renews via cron)

STEP 6 — Seed super admin:
  Run: npm run seed:superadmin
  Creates the initial super_admin account from SUPER_ADMIN_EMAIL in .env
